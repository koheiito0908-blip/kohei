# スイッチングヒーローズ 編成最適化ツール (非公式)

放置型RPG「スイッチング ヒーローズ」の英雄・ペット・装備データをもとに、
所持リソースから最適な編成を提案するツールです。

## 現状の設計方針(重要)

このツールを作るにあたり、以下を確認・検討した結果、**データは自動収集せず、手動登録
方式で始めています**。

- **Discordコミュニティのログを無断で自動収集することはしません。** 一般参加者の
  アカウントで自動化するのはDiscordの利用規約(セルフボット禁止)に反し、アカウント
  BANのリスクもあります。データが欲しい場合は、サーバー管理者に「read-only botの
  設置」を相談するのが唯一の正攻法です。
- 攻略サイト(ゲームウィズ等)は情報が古く、上位プレイヤーの実践知とズレがあるため
  主データ源にしていません。またこの開発環境からは一般サイトへの直接アクセスが
  ネットワークポリシーでブロックされており、動作確認もできていません。
- そのため v1 は **人が読んで手動で登録する** 前提で設計しています。
  `docs/` のWebアプリに「データ登録」タブがあり、Discordや攻略サイトで
  **自分の目で読んでコピーした** テキストを貼り付けると、ブロック分割や
  既知データとの一致ハイライトなど「構造化の補助」だけを行います。実際に
  データベースへ入れるかどうかは常に人間が確認してから `docs/data/*.json` に
  反映します。

## 構成

```
switching-heroes/
  docs/                  # 静的Webアプリ本体(GitHub Pagesで配信する想定)
    index.html
    app.js               # データ読み込み・編成シミュレーター・貼り付け登録支援
    style.css
    data/
      schema.md          # heroes/pets/gear.json の項目定義
      heroes.json        # 英雄データ(ダミー1件のみ。実データに置き換えてください)
      pets.json          # ペットデータ(同上)
      gear.json          # 装備・カードデータ(同上)
```

## ローカルで試す

```bash
cd switching-heroes/docs
python3 -m http.server 8080
# http://localhost:8080 を開く
```

ビルド不要の素のHTML/CSS/JSです。`docs/data/*.json` を編集してブラウザをリロード
すればすぐ反映されます。

## データの追加方法

1. `docs/data/schema.md` の形式に沿って `docs/data/heroes.json` / `pets.json` / `gear.json` を
   直接編集してもよいですし、
2. Webアプリの「データ登録」タブで、貼り付け→フォーム入力→ドラフトJSONをコピー、
   という流れで整形してから貼り付けてもOKです。
3. **出典(`source`)と日付は必ず入れてください。** 環境が変わるゲームなので、
   いつの情報かが編成シミュレーターの信頼性に直結します。

## 編成シミュレーターのロジック(v1)

実際のダメージ計算式やスキルの相互作用式はまだ持っていないため、v1は
**Tier評価ベースのルールベーススコアリング**です(`docs/app.js` の `scoreTeam`)。

- Tierスコア: S=4, A=3, B=2, C=1, D=0 の合計
- 役割多様性ボーナス: 編成内のユニークな `role` 数 × 1.5
- シナジーボーナス: `synergy_tags` が一致するペアごとに +0.5

所持英雄が15人以下なら全組み合わせを総当たりし、それ以上なら貪欲法+局所探索
(スワップ)で近似します。ペットはTier+シナジー一致度、装備は `recommended_for`
に基づく貪欲割り当てで選びます。

**これは本当の最適解ではなく、現状の評価データから導ける「もっともらしい候補」
です。** 実際のスキル効果・ダメージ式・敵構成に応じた計算に発展させるには、
ゲーム内の数値データ(スキル倍率、ステータス計算式など)が別途必要です。今後
そうした情報が手に入り次第、スコアリングを差し替えていく想定です。

## Webサイトとして公開する場合

このリポジトリは同じブランチ内に別プロジェクト(ボートレース予想)があり、
GitHub Pagesは1リポジトリにつき1サイトしか持てません。ボートレース予想側が
「ブランチの `/docs` を配信」する設定を使っているため、このツールを
GitHub Pagesで公開するには、以下のいずれかを選ぶ必要があります。

- リポジトリのPages設定を「GitHub Actions」ソースに切り替え、
  `.github/workflows/deploy-switching-heroes.yml` に配信を任せる
  (ボートレース予想のPagesは止まります)
- このツール専用の別リポジトリを用意する
- 公開はせず、ローカルの `python -m http.server` だけで使う

差し当たりはローカル起動での利用を想定しています。公開したくなったら教えてください。
